# Verified form referral credit
All referrals, including existing ones, remain pending unless their account email hash matches a verified submission from the configured form. Existing accounts/referrer attribution are preserved. Each email contributes at most one completion. Website passwords, order details, payment choices and pickup information are not sent to the tracker. Submission proves neither payment nor order confirmation. Website email ownership remains unverified; matching proves a form submission for that email, not necessarily control of the website account.

After deploying the website code, open the form editor, choose Apps Script from the menu, paste google_form_sync.gs into the script project, and save. In Project Settings add script property FORM_WEBHOOK_SECRET with the same private value as Render. Never put the secret in source code, chat, or screenshots. Run installReferralSync and authorize access to the form, triggers and external requests. Do not run onReferralFormSubmit manually. Run syncResponses to import up to 50 earlier responses per run; repeat for larger sets. An hourly trigger continues synchronization and retries missed submissions. Pending referrals remain pending until authenticated notifications arrive.

Only one editor should install the triggers, using an account that will retain access. Installable triggers run under the installer. Free service wake-up or quota errors can delay credit; check Apps Script Executions and rerun syncResponses. Retrying is safe because completions are deduplicated. No script has been installed or authorized merely by committing this file. No Google Form questions are changed.

The new form_completion table stores hashed emails, response IDs and receipt times. Hashing is not anonymization. Authenticated webhook payloads use HMAC-SHA256 over exact JSON. Safeguard the secret and form-editor access. This demo loads account records to compute dashboard counts; migrate to indexed aggregate queries for larger deployments.
